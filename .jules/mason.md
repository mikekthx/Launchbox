## 2026-05-11 - Move UI Focus Logic to Code-Behind
**Learning:** While routing standard interactions (like clicks) to ViewModel Commands is good practice, routing low-level raw UI input events (like `VirtualKey.KeyDown`) into the ViewModel leaks UI framework concerns into the presentation logic. It also requires bouncing events back to the View to manipulate UI element focus.
**Action:** When handling complex keyboard input that triggers programmatic focus shifts, keep the input event handler (e.g., `KeyDown`) in the View's code-behind. The code-behind should invoke a clean ViewModel method (e.g., `TryLaunchSelected()`) for business logic and manually manage the resulting UI focus state.

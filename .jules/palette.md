## 2026-07-29 - UIA LabeledBy vs Name Precedence
**Learning:** In WinUI 3, assigning `AutomationProperties.LabeledBy` on a control completely overrides any `AutomationProperties.Name` defined for that control (including those populated via `x:Uid` from `.resw` files). If a single visual header labels multiple distinct inputs (e.g., a "Global Hotkey" header for both a modifier dropdown and a key text box), applying `LabeledBy` to both inputs causes the screen reader to announce both identically, discarding their distinct names.
**Action:** Only use `AutomationProperties.LabeledBy` when the label maps 1:1 to a single input. For complex multi-input groups, rely on distinct `AutomationProperties.Name` values for each control to ensure proper context.
